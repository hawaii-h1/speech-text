# SpeechText

macOS menu bar voice-to-text app. Records audio via a global hotkey, transcribes speech, and pastes the result at the cursor position in the previously active app.

The app was called **VoicePeter** until the 2026 rebrand, and the rebrand itself first shipped the name misspelled (**SpeachText**). Both steps moved the bundle identifier (`com.voicepeter.app` → `com.speachtext.app` → `com.speechtext.app`), and macOS keys microphone, speech-recognition and accessibility grants to it, so each change re-asks for all three. Two one-shot migrations keep the rest from reading as a factory reset, and both walk a *chain* of old names rather than a single one: `TranscriptionHistory.adoptPreRenameStore()` moves the newest surviving Application Support folder (`SpeachText/`, else `VoicePeter/`) to `SpeechText/`, and `adoptPreRenameDefaults()` (Settings.swift) copies `SettingsKeys.portable` out of `com.speachtext.app`, then `com.voicepeter.app` — API keys, shortcuts and prompt presets included — newest domain first, never overwriting a key already present. `hasRegisteredLaunchAtLogin` is deliberately left behind: it records a registration made under an *old* bundle identifier, and carrying it over would leave the renamed app convinced it is already a login item when it is not.

## Build & Run

Open `SpeechText/SpeechText.xcodeproj` in Xcode and build (Cmd+B) / run (Cmd+R). Three Swift packages, all pinned in `project.xcworkspace/xcshareddata/swiftpm/Package.resolved`: WhisperKit (`argmaxinc/argmax-oss-swift`) and FluidAudio (`FluidInference/FluidAudio`) for the two local speech engines, and Sparkle (`sparkle-project/Sparkle`) for updates; everything else is Apple frameworks. See **Three dependencies, one file each** below.

`scripts/rebuild.sh` (a plain shell script the user runs themselves) builds Release, installs to `/Applications/SpeechText.app`, stops every running instance under every name the app has shipped as, and relaunches it; `--status`, `--rollback` and `--tag X.Y.Z` are described in `docs/rebuild.md`.

Target: macOS (native Swift/SwiftUI). The app runs as a menu bar agent (`LSUIElement = true`) with no main window; by default it gains a Dock icon only while Settings, History or another ordinary window is open (`DockIconMode`).

Both configurations build with the **hardened runtime**, and `SpeechText.entitlements` declares every protected resource it gates (audio input, and Apple Events for the AppleScript fallback that re-activates the target app) — a feature that touches a new one needs its entitlement there, or it fails only in signed builds. Releases are Developer ID–signed, notarized disk images made by `scripts/package-release.sh`; pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`, which opens a *draft* GitHub release. Credentials live only in repository secrets. `docs/releasing.md` has the one-time setup — including why the signing team must be chosen before the first public release: the team ID is part of the identity macOS keys every permission grant to.

## Commits

Every commit is signed off — `git commit -s` (and `git commit --amend -s` for one that was not), merge commits included. CI's `DCO sign-off` job fails a pull request if any commit in its range lacks the `Signed-off-by:` trailer. `git config core.hooksPath .githooks` turns on the `prepare-commit-msg` hook that adds it automatically (see CONTRIBUTING.md › Hooks), but a worktree without the hooks enabled commits unsigned, so pass `-s` regardless.

## Naming

When the user names something, the word may be one they coined rather than the accepted one. Before that name goes into the code, the settings keys, the UI or these docs, check whether the thing already has a standard name — in the platform's vocabulary or the field's — and say what it is, so the choice is deliberate. Where no standard name exists, say that too. A competitor's product name is not a standard term and stays out of the repo.

## Tests

`xcodebuild test -project SpeechText/SpeechText.xcodeproj -scheme SpeechText -destination 'platform=macOS'` runs the `SpeechTextTests` unit-test bundle (sources in `SpeechText/SpeechTextTests/`). It is **standalone — no `TEST_HOST`, no `@testable import`**: the app is an LSUIElement agent that prompts for microphone access at launch, so hosting tests inside it would hang a headless run. Instead the test target compiles a curated subset of app sources directly (AudioBufferWriter, STTProvider, StreamingSTTProvider, RecordingConfiguration, Settings, LLMProvider, PromptPresets, TextRefinementService, TranscriptSpan, TranscriptMerge, TranscriptCleanup, InsertionLedger, DeliveryTier, FinalizePass, FocusContext, DebugLog, SystemCapabilities, LocalModelCatalog, OllamaProvider, InlineDelivery, RecognitionSession, BatchRecognitionSession, StreamingRecognitionSession, DictationTrace, OverlayPlacement, DictationHotkeys, ShortcutConflicts, SelectionEdit, SetupServices). The consequence: **a new app file that test code needs must be added to both targets' Sources phases in `project.pbxproj`** — and so must anything a file already in the subset comes to depend on. A file in the subset must not reach into the app's view or state graph (SwiftUI views, `AppState`, `SpeechEngine`), or the subset stops being a subset — and it must never `import WhisperKit` or `import FluidAudio`: the standalone bundle does not resolve packages, which is why the local tier reaches both its engines through the `LocalSTT` registration box.

Covered: `PCMDownsampler` (3:1 downsample frame counts, stereo→mono downmix, resampler state across calls), `AudioBufferWriter` (write → readable 16 kHz mono file of the right duration, `noAudio` on empty, `reset`), the multipart form helpers and `multipartAudioPart`, `RecordingConfiguration`'s derivations (`streams`, `batchModel`, and `cloudLanguage`/`historyLocale` — Auto tells a cloud model nothing), the OpenAI tier (its realtime model alone streams and maps back to the upload model, the catalogue offers neither the silence-hallucinating `whisper-1` nor the diarizing model, and `OpenAIRealtimeProvider.encodeSessionUpdate` asks for 24 kHz with turn detection off — a session left unconfigured transcribes nothing), `TextRefinementService.parse` (mode marker, code-fence stripping rules), and `TranscriptSpanLayer`'s whole state machine (a partial keeping its identity while it grows, a commit adopting it, only the increment of a cumulative `committed` becoming a span, a segment result that matches leaving the spans alone, and a `Frozen` span surviving every rewrite path), `TranscriptMerge` (a commit that restates everything replacing it, a partial reduced to what it adds, a revised word not defeating the match, and a two-word repeat left alone as speech), `TranscriptCleanup` (hesitations dropped with their punctuation, look-alike words kept, stretched letters and trailing ellipses, and the monotonicity that keeps it safe on cumulative text), `InsertionLedger` (a span found where it was recorded, followed when the document shifted around it, and *refused* when the user edited over it or when it appears twice; the shifting of neighbouring records) and `DeliveryTier` (an app whose range write is accepted but does not read back is Tier B; AI mode delivers nothing early in any tier unless the AI draft is opted in, and then only in Tier A), `FinalizePass` (a badly cut name replaced as one range covering every record; a refusal — not a skip — when a record was edited over or the user typed between two records; extend / replace / leave decided by tier, frozen text and an empty result; and a collapsed ledger leaving the stop nothing to paste) and `DictationHotkeyGesture` (the press table, a hold stopping on its owner's release, a lone tap cancelled by its timer and a double tap locking the dictation on) and `EditHotkeyGesture` (a double press within the window sends with no instruction, a later one stops; with hold to talk a lone tap cancels only when its window runs out, and a double tap's second release does nothing) and `SelectionEdit` (a selection trimmed to its words in UTF-16, a VS Code line copy refused, a Tier A record that a changed document makes unreplaceable, and the edit prompt keeping `<selected_text>` apart from `<instruction>`) and `FocusContext` (a password manager yields nothing and a secure field keeps only the app's name; a hostile window title cannot close the `<context>` block; the system prompt describes the block only when asked) — plus `UndeliveredRemainderTests`, which is the anti-duplication guard: what the stop still owes after spans were pasted during the recording, and nil when the final text disagrees with them instead of extending them — and `OnboardingTests` (who sees setup at launch — a new install, an unfinished setup, but not an install that predates it; each service's key shape, so nothing else on the clipboard is taken for a key; and the key check's verdicts, a scoped ElevenLabs or OpenAI key counting as valid) — and `LocalModelsTests` (both catalogues heaviest-first with every tier pick present, each speech model paired with the engine that can run it, and Parakeet counted installed only when all four of its bundles are on disk — checked against a temporary directory, never the user's own, the speech and chat recommendations across memory, disk headroom and Intel-vs-Apple-Silicon, `strippingReasoning`, `MacTier` across the whole current lineup (MacBook Neo to Mac Studio M5 Ultra), each tier's recommended / best-quality pair and the step-down at the bottom of a tier, the local tier's `RecordingConfiguration` derivations and `batchUnavailableReason`, and an unregistered local provider throwing rather than returning empty text). Beyond single types, `DictationReplayTests` plays whole inline dictations through the app's own code — see **Dictations are replayed, not hosted** — and `RecordedTraceTests` replays every trace in `SpeechTextTests/Traces/`. Tests never touch `UserDefaults` — the user's real API keys live in the `com.speechtext.app` domain — so anything that reads defaults (`RecordingConfiguration.current()`, `PromptPresetStore.load()`) is bypassed by constructing values directly.

## Architecture

All source files live in `SpeechText/SpeechText/`; the unit tests live in `SpeechText/SpeechTextTests/` (see **Tests** above). Three SPM packages: WhisperKit, imported by `LocalWhisperRuntime.swift` only; FluidAudio, imported by `LocalParakeetRuntime.swift` only; and Sparkle, imported by `UpdateChecker.swift` only.

### Core Components

- **`App.swift`** — Entry point. `SpeechTextApp` is the `@main` SwiftUI app whose only scene is `Settings { SettingsView() }` — the one Settings window, which the app menu's Settings… (⌘,) opens on its own once the Dock icon brings that menu in. `SettingsOpener` lets AppKit code (the status menu, a Dock-icon click) open the same scene: since macOS 14 `showSettingsWindow:` silently does nothing, so a view hosted in a never-shown borderless window hands out SwiftUI's `openSettings` action. `AppDelegate` manages the `NSStatusItem` (menu bar icon/menu). `AppState` orchestrates recording flow, overlay/panel lifecycle, previous-app tracking, and paste-back. Also contains `ObservedOverlay`, a small wrapper view that bridges `SpeechEngine` to `RecordingOverlayView`. And `AppVersion`, the menu's first line (`0.9.0 (build 47 · a18a7d1 · date)`, click to copy): the commit and date come from `$(SPT_GIT_COMMIT)` / `$(SPT_BUILD_DATE)` placeholders in `Info.plist` that `scripts/rebuild.sh` fills on the `xcodebuild` line — an Xcode ⌘R build leaves them empty and the menu says `(dev)`.
- **`SpeechEngine.swift`** — the recording engine. Owns the microphone (`AVAudioEngine`, the tap, `barLevels` per-segment RMS), the per-segment `AudioBufferWriter`, the start/pause/resume/stop lifecycle, the device-change restart, and the History bookkeeping (`recordOutcome`, fed by each segment's `RecognitionOutcome`). Recognition itself is delegated to one `RecognitionSession` per segment, created in `setupRecordingSession` and cancelled in `cleanup`; the session's `.live(committed:partial:)` events become `liveText`, its `.failure` becomes `errorMessage`. State lives in a single stored `phase: RecordingPhase` (idle / starting / recording / paused(segmentInFlight:) / finishing); `isRecording`, `isPaused`, `isTranscribing` and `isStartingEngine` are computed from it, so the views and `AppState` read the same API as before. Exposes `liveText` — now a computed view over `spanLayer.segmentText` rather than a stored string — for in-progress transcription, `finalText` for completed transcription, `editedText` for the user-editable result, `pendingInsertionText` (a segment is ready for cursor insertion), and `awaitTranscription()` (resumes on the phase change whose `isTranscribing` flips false, after `finalText`/`errorMessage`/`lastRecordID` are already written).
- **`RecognitionSession.swift`** — the tier abstraction: `RecognitionSession` protocol (`start` / `feed(native:pcm16:)` / `pause` / `finish` / `cancel`, one instance per segment), `RecognitionEvent` (`.live(committed:partial:)` — kept apart rather than pre-joined so a later span layer can map them onto partial/commit/revise — and `.failure`), and `RecognitionOutcome` (trimmed text, error, the segment's audio file whose ownership passes to the engine, cancelled). No `Speech` import, so it is in the test subset with the streaming and batch sessions.
- **`RecognitionSessionFactory.swift`** — `makeRecognitionSession(configuration:writer:recognizer:)`, the one place that knows which tier a configuration selects. App target only: it names `AppleRecognitionSession`.
- **`TranscriptSpan.swift`** — the span layer: `TranscriptSpan` (id, segment, text, and the state it is in — `provisional` / `committed` / `revised` / `settled` / `frozen` / `dropped`) and `TranscriptSpanLayer`, which turns the sessions' *cumulative* `committed` / `partial` strings into spans with identity. Pure logic — no engine, no view, no clock — so `PureLogicTests` covers the whole machine. Phase A of the chunked-transcription spec; `revise`/`freeze` are the hooks phase C's finalizing pass and the Record Window's hand edits will use.
- **`InsertionLedger.swift`** — `InsertionRecord` + `InsertionLedger`: what a sink has already been handed, where it landed, and what the sink holds there. Pure logic in both targets, covered by `InsertionLedgerTests` and `UndeliveredRemainderTests`. `resolve(span:in:)` is the "still untouched?" guard a replacement runs first; `remainder(of:)` is what the stop subtracts so a dictation delivered during the recording is not pasted a second time.
- **`DeliveryTier.swift`** — `AXTextProbe` (what the Accessibility API will let us do to the focused element) and `DeliveryTier` (`.a` / `.b`) with the pure `resolve(isOwnSurface:probe:)`, `deliversDuringRecording(aiMode:)` and `recordsRanges`. No AX calls of its own — `PasteService.probeFocusedText` makes them and hands the answers in, which is what keeps the decision in the test subset.
- **`FocusContext.swift`** — where an AI dictation will land: app name, bundle ID, window title and the field's label, read by `PasteService.readFocusContext` and handed to `capture`, which decides what may leave the machine (nothing from a password manager in `excludedBundleIDs`, only the app from a secure text field). `clean` flattens each value to one bounded line and swaps `<`/`>` for `‹`/`›`; `promptBlock` renders the `<context>` block. Pure logic in both targets. Always on — there is no switch; the exclusions are the privacy boundary.
- **`FinalizePass.swift`** — the stop's single write (D12), as pure logic in both targets: `decide(ledger:authoritative:tier:hasFrozenSpans:)` (`nothingDelivered` / `extend` / `replace` / `leave`), `plan(ledger:document:replacement:)` (the delivered text as one untouched range in the document, or nil) and `InsertionLedger.collapse(into:landed:)`. `PasteService.replaceLastInsertions` does the AX I/O around the plan; `InlineDelivery.finalize` calls it, from `SpeechEngine.onFinalize` through `AppState`.
- **`InlineDelivery.swift`** — one inline recording's delivery, as pure logic in both targets: `begin` (tier, and whether spans go out while speaking), `enqueue` (serialised pastes; spans stay queued while the target app is not in front), the ledger, `finalize` (the stop's correction), `whenIdle` (the stop's result waits for a paste still landing), `stopResult` (what the stop does: paste the remainder, notice, refine…) and `deliverAIResult`. Its I/O goes through `InlineDeliveryTarget`: `AccessibilityDeliveryTarget` (PasteService.swift) in the app, `FakeApp` in the tests. `AppState` keeps the overlay, notices, Record Window fallback and the LLM call. Also `PasteLanding`.
- **`DictationHotkeys.swift`** — `DictationHotkey` (inline / AI), `DictationHotkeyAction` and `DictationHotkeyGesture`: one table for a press (idle → start in that mode; recording → the same mode's shortcut stops, the other switches; starting → the same cancels, the other switches; transcribing/refining → cancel) and, with `holdToTalk`, the release of the shortcut that started the dictation (its *owner*) stops it; a release within `tapThreshold` (0.3 s) is a tap, which cancels when `tapWindowExpired` fires `doubleTapWindow` (0.35 s) later — unless the same shortcut is pressed again first, which is a double tap and locks the dictation on hands-free (`.lock`; the other shortcut inside the window cancels); while the owner is held, each press of the other shortcut flips the mode (plain ↔ AI) instead of stopping. Pure logic in both targets, covered by `DictationHotkeyGestureTests`; `AppState.hotkeyPressed` / `hotkeyReleased` supply the phase and perform the action, and the menu items go through the same press table.
- **`SelectionEdit.swift`** — the Edit shortcut's pure half: `EditHotkeyGesture` (toggle: a press starts, a second press sends the instruction, a second press within `doubleTapWindow` (0.35 s) sends with none; hold to talk: a hold sends on release, a double tap sends with none, a lone tap cancels when `tapWindowExpired` fires; a press while busy cancels — the first press never waits, the second is read retroactively), `CapturedSelection` (the text, and in Tier A the `InsertionRecord` of where it is), and `SelectionEdit` (`words(in:of:)` trims the selection to its words so a trimmed model answer does not swallow the newline after it, `isEmptySelectionLineCopy` for VS Code's copy-the-line-on-empty-selection, `changes`, `preservingEdges`, `maxCharacters`). Covered by `EditHotkeyGestureTests` and `SelectionEditTests`; `AppState`'s "Editing the selection" section performs the actions.
- **`DictationTrace.swift`** — `DictationTrace` (a flat, hand-editable JSON record of one streamed inline dictation: provider events as they arrived, stop, fallback answer, rewrite, corrections, pastes, and an optional reviewed `expectedDocument`) and `DictationTraceRecorder` (`current` is non-nil only while `recordDictationTraces` is on). Written to `Application Support/SpeechText/Traces/`, copied into the tests by `scripts/import-trace.sh`.
- **`TranscriptMerge.swift`** — `joinedTranscript` plus the merge the streaming tier needs: `transcriptWords` (punctuation-insensitive words anchored in their source), `transcriptOverlap` (how much of what is already held the incoming text repeats, and whether it re-states all of it), `mergedTranscript` and `transcriptContinuation`. Pure string logic, in both targets, covered by `TranscriptMergeTests`.
- **`TranscriptCleanup.swift`** — `cleanedTranscript`: drops hesitation sounds (`е-е-е`, `а-а`, `еее`, `м-м`, `хм`, `uh`, `um`) by their shape, collapses tripled lowercase Cyrillic letters ("тооо" → "то"), and turns a word-final `...` into a full stop. Lexical fillers ("ну", "типу") are kept — "типу" is also a real genitive. Pure logic, in both targets. `RecordingConfiguration.cleaned` applies it when `removeDisfluencies` is on, and always applies `DashStyle`: Scribe's `—` redrawn as `–` (default), `-`, or left alone — the same dash in the same place, never removed or chosen from the surrounding words (the user writes "Книга – це" on purpose). A glued em dash gets spaces; hyphens and `2–5` ranges are untouched. `TextRefinementService.refine` applies the same style to the LLM's reply.
- **`AppleRecognitionSession.swift`** — the on-device tier: `SFSpeechRecognizer` request/task, the 50 s chunk rotation (SFSpeechRecognitionTask stops accepting audio after ~1 min; rotation commits the live text and starts a fresh request under the running tap, discarding late callbacks by token and clearing a stale `isFinal`'s `finalText` so an early final in chunk 1 cannot swallow later chunks). `pause()` hands the joined live text back immediately (task and request stay alive for the eventual stop); `finish()` calls `endAudio` and waits ≤ 0.5 s, resolved early by `isFinal`.
- **`BatchRecognitionSession.swift`** — the upload tier: `finish()` writes the engine's writer to a file and uploads it; on failure the file is handed back in the outcome (not deleted) so the engine can archive it for a History retry. No live text; `feed` is a no-op because the engine's writer already collects the audio.
- **`StreamingRecognitionSession.swift`** — the realtime tier, a composition: wraps a `StreamingSTTProvider` *and* a `BatchRecognitionSession` fallback. `feed` sends the writer's 16 kHz bytes; events mirror into committed/partial (emitted as `.live`); a broken stream sets an internal `failure` and never surfaces as `.failure` — `finish()` then clears the ghost text and hands the segment to the wrapped batch session, which uploads the same writer's file.
- **`STTProvider.swift`** — `STTProviderType` enum (`.apple`, `.groq`, `.elevenlabs`, `.openai`, `.local`), `BatchSTTProvider` protocol, the shared `makeBatchProvider(configuration:)` factory (used by both live recording, the streaming fallback and History retries), plus `GroqSTTProvider` (multipart POST to `api.groq.com/openai/v1/audio/transcriptions`), `ElevenLabsSTTProvider` (multipart POST to `api.elevenlabs.io/v1/speech-to-text`) and `OpenAISTTProvider` (multipart POST to `api.openai.com/v1/audio/transcriptions` — the same shape and Bearer auth as Groq, whose endpoint is literally the OpenAI one, but its own type so the error text names the right vendor and the reply's `languages` field is logged), and `multipartAudioPart(for:)`, which reads the upload's filename and MIME type off the file's extension. Also `STTTuning`: every latency/quality knob the cloud providers use (the 1.0 s realtime VAD silence threshold, the 4 s `finish()` wait, the 100 ms send chunk, the 0.4 s commit padding, the 10 s pre-`session_started` buffer bound, the 0.2 s commit-reply grace, the 120 s / 300 s batch timeouts, and the `tag_audio_events=false` / `no_verbatim=true` Scribe flags), each with a doc comment saying why — so a value measured against the live service is never re-derived by feel in a second file. Includes `Data` extensions for multipart form encoding and `GroqError` for API error handling.
- **`StreamingSTTProvider.swift`** — `StreamingSTTProvider` protocol (push 16-bit PCM in at the provider's own `sampleRate`, get `partial` / `committed` / `failed` events out over an `AsyncStream`), `makeStreamingProvider(configuration:)` (returns nil unless `configuration.streams`, then picks by engine), `ElevenLabsRealtimeProvider` (WebSocket to `/v1/speech-to-text/realtime` with `scribe_v2_realtime`, `commit_strategy=vad`, `vad_silence_threshold_secs` and `no_verbatim` from `STTTuning` — the server echoes both in `session_started.config`, which the debug log prints; `finish()` sends a last chunk with `commit: true` and waits — bounded — for its transcript) and `OpenAIRealtimeProvider` (WebSocket to `/v1/realtime?intent=transcription` with `gpt-live-transcribe` — see **OpenAI's stream is a different shape** below).
- **`RecordingConfiguration.swift`** — the settings one recording session runs with: `provider`, `locale`, the Groq, ElevenLabs and OpenAI keys and model IDs, read from UserDefaults once by `current(locale:)` (the locale defaults to `resolvedLocale()`, so it follows the keyboard layout) and carried through the session. Derived answers live here rather than in the factories: `cloudLanguage` (what a cloud provider is told — nil on Auto, see **Auto language detection**), `historyLocale` (what the record says the language was), `streams` (a realtime model is selected — ElevenLabs' or OpenAI's), `batchModel` (the upload model — each realtime model → its vendor's batch model, Apple → the Groq model, since none of them exists behind an upload endpoint). History retry asks `batchUnavailableReason()` before starting instead of firing a request with an empty key or no installed model. `makeBatchProvider(configuration:)` and `makeStreamingProvider(configuration:)` take it; History retry reads a fresh one so a retry honours the *current* settings.
- **`AudioBufferWriter.swift`** — Collects the segment's audio for batch STT providers and writes it to a temporary audio file via `AVAudioFile` — FLAC by default (`preferredUploadCodec`: lossless, about half the bytes of WAV, accepted by both Groq and ElevenLabs), WAV if the encoder throws. The file's extension is the contract: the batch providers pick the multipart filename and MIME type from it (`multipartAudioPart`) and the History archive keeps it, so a `.wav` archived before FLAC uploads existed still retries. Owns the session's `PCMDownsampler` (a stateful `AVAudioConverter` wrapper that turns each tap buffer into 16 kHz mono Int16) and converts *as audio arrives*, so `writeAudioFile()` is a single encoder pass over bytes that already exist rather than a conversion paid all at once at stop; `append` returns the converted bytes so the streaming provider sends the same ones. When no converter exists for the hardware format it falls back to native buffer copies converted at stop (native-format WAV as a last resort). Also cleanup of temp files.
- **`TranscriptionHistory.swift`** — `TranscriptionRecord` + an `@Observable` store persisted to `Application Support/SpeechText/history.json`, newest first and capped at 300 — `adoptPreRenameStore()` moves a pre-rename `VoicePeter/` folder there once, so the path in an old install's on-disk layout is not the one in the code. Failed and empty results keep their audio file (`.flac`, or `.wav` for older entries) under `Recordings/` for 7 days so they can be retried. `TranscriptionRecord.Refinement` records the LLM pass: `inputText` (what was actually sent — the Record Window refines its whole text area, not just one segment), `outputText`, `presetName`, `provider`/`model`, and `errorMessage` when the pass failed. `record.text` always stays the transcription before the LLM (hesitation cleanup already applied); `deliveredText` returns what the user actually received. `correctionApplied` (optional) says whether the stop managed to correct text delivered during the recording: nil when there was nothing to correct, false when it was refused. Writes are coalesced: a mutation schedules one write 250 ms out and a burst (record, refinement, correction flag) re-schedules it rather than re-encoding all 300 records three times; `flush()` writes synchronously and `applicationWillTerminate` calls it.
- **`HistoryView.swift`** — History browser (`HistoryWindow`): filterable list, retry-from-archived-audio, copy, and a two-pane “Dictated / AI output” comparison for entries that went through the LLM.
- **`LLMProvider.swift`** — `LLMProviderType` enum (`.groq`, `.anthropic`, `.openai`, `.ollama` — `needsAPIKey` is false for Ollama, where `isConfigured` means a model is chosen), `LLMChatProvider` protocol, `OpenAICompatibleLLMProvider` (one implementation covering Groq and OpenAI, which share the `/chat/completions` shape but not its parameters — see its `Dialect`: Groq takes `max_tokens`/`temperature`, OpenAI's GPT-5.x reasoning models reject both and use `max_completion_tokens`) and `AnthropicLLMProvider` (raw `POST /v1/messages`; sends `output_config.effort = low` where supported, opts into server-side refusal fallbacks on Opus 5, and treats `stop_reason == "refusal"` as an error). `LLMConfiguration` resolves provider/key/model from UserDefaults and builds the provider.
- **`PromptPresets.swift`** — `PromptPreset` model (`name`, `whenToUse`, `instructions`) and `PromptPresetStore` (JSON in UserDefaults, six built-in defaults with fixed UUIDs, plus the "default preset" pointer).
- **`TextRefinementService.swift`** — Builds the routing system prompt from the presets, sends the transcript wrapped in `<transcript>` tags — preceded, for the AI hotkey, by the `<context>` block of the app the cursor was in (`userMessage(transcript:context:)`; the Record Window passes none) — and parses the reply's leading `<<mode:NAME>>` marker (plus a wrapping code fence, if any).
- **`SystemCapabilities.swift`** — a plain value describing the Mac: chip name (`machdep.cpu.brand_string`), Apple Silicon or not, the total physical core count (summed over `hw.nperflevels`, because an M1's levels are Performance + Efficiency and an M5's are Super + Performance), installed RAM and free disk (`volumeAvailableCapacityForImportantUsage`). Also `MacTier` — intel / entry (8 GB, MacBook Neo) / standard (16 GB) / plus (24–32 GB) / pro (36–64 GB) / max (96–128 GB) / ultra (256 GB+), decided by memory, never by model name. `current()` is the only sysctl reader in the app; everything that recommends a model takes a `SystemCapabilities` as a *parameter*, so recommendations are testable pure functions. Integer sysctls are read at whatever width the kernel reports, because `hw.memsize` is 64-bit and `hw.perflevel0.physicalcpu` is 32-bit.
- **`LocalModelCatalog.swift`** — `LocalSTTEngine` (`whisperKit` / `parakeet`), `LocalSTTModel` and `localSTTModels` (Parakeet v3 plus five WhisperKit variants, heaviest first, sizes read from the HuggingFace tree API), `TierPicks` and `localSTTPicks(for:)` (per tier, a *recommended* and a *best quality* candidate list), `firstFitting` (shared with the chat side: first candidate clearing its RAM floor and fitting on disk with 1 GB headroom), `recommendedLocalSTTModel(for:)` / `bestQualityLocalSTTModel(for:)` and the one-line reason, the on-disk layout (`localModelsDirectory()`, `isLocalModelInstalled` — a directory test callable from any thread; any `.mlmodelc` for Whisper, but all four named bundles for Parakeet, whose install is four separate fetches), `LocalModelError`, and the `LocalSTT` registration box that `makeBatchProvider` calls. Unregistered (the test target's state) the box yields `UnavailableLocalSTTProvider`, which throws.
- **`LocalModelStore.swift`** — `@MainActor @Observable` owner of installs: per-model `InstallState` (not installed / downloading(fraction) / installed / failed), `install` (downloads into a per-model staging folder, *moves* the result to `Models/<variant>/` so our layout never depends on either engine's cache, then prewarms), `cancelInstall`, `remove` (also releases the loaded model). The `LocalSTTRuntime` protocol lives here, and `runtime` is a `(LocalSTTEngine) -> LocalSTTRuntime` closure, so a download is dispatched per *model* rather than once for the store. `registerLocalSTT()` is here too: it now names both engines, so it belongs to neither runtime file. App target only — it touches `TranscriptionHistory` (see **Model storage and the rename migration**).

- **`LocalParakeetRuntime.swift`** — the one file that imports FluidAudio, and the same four pieces in the same order: `ParakeetRuntime` (download via `AsrModels.download(to:)`, transcribe through `AsrManager` with a script hint on anything but Auto), `ParakeetPipelineCache`, `ParakeetLocalProvider`. Two sharp edges are absorbed here. `AsrModels.download(to:)` writes to the *parent* of the directory it is given plus FluidAudio's own folder name, so the staging folder is named for the repo and the store's move renames it. And the encoder precision (`.int8`) has to match on download and load, because the loader opens the file it names — `.int8V2` and `.int4` are other files in the same repo.
- **`UpdateChecker.swift`** — the one file that imports Sparkle: the app checks `…/releases/latest/download/appcast.xml` once a day, offers what it finds, and installs it after the user agrees. `isConfigured` is false when `Info.plist` carries no `SUPublicEDKey` — Sparkle's own answer to a missing key is a modal alert on every launch, so instead the menu item and the Settings rows are simply absent and the updater is never started. `isDevelopmentBuild` (no stamped commit, or build number 1) starts no updater at all: such a build is older than every release, and every Sparkle setting is stored in the app's *own* defaults domain — which a ⌘R build shares with the copy in `/Applications`, so a run that merely switched the schedule off would switch updates off for the installed app, permanently and invisibly. Updates are exercised from a `rebuild.sh` install. Every update is signed with an EdDSA key that is the project's own, independent of the Apple certificate — see `docs/releasing.md`.

- **`LocalModelsView.swift`** — the Settings rows for both local tiers, kept apart from `MenuBarView.swift` so onboarding can reuse them: `LocalSpeechModelsView` (hardware summary and tier, recommendation reason, one row per model with Download / Cancel / Remove and a progress bar, disk used, Show in Finder) and `OllamaModelsView` with its `OllamaModelManager` (not running → a "Get Ollama…" link and Check Again; running → the models that fit this Mac, the heavier ones folded into a disclosure, plus any other model already in Ollama). ### Recording Modes

- **Inline recording** — Triggered by global hotkey (default: `Ctrl+Shift+Q`). Shows a small floating overlay (`RecordingOverlay.swift`) in the bottom-right corner, or wherever the user dragged it. With a streaming model (`scribe_v2_realtime`) the overlay shows the transcript as it is built and corrected, and the text is pasted once, at the stop — see **A streaming recording is built on the overlay**. On stop, transcribed text is pasted at the cursor in the previously focused app via `PasteService`. Falls back to opening the Record Window if accessibility permission is missing or the previous app couldn't be detected.
- **Switching mode, and holding to talk** — during an inline or AI dictation the *other* mode's shortcut switches it over (the overlay's tint follows) and its own shortcut stops it. Plain → AI turns what was already pasted into an AI draft (`InlineDelivery.switchToAI`: no more spans while speaking, `deliverAIResult` replaces it at the stop) and is refused with a notice in Tier B once anything has gone out, because the rewrite could only land under the raw text. AI → plain changes nothing while recording: the stop pastes whatever was not delivered. `FocusContext` is therefore read for every inline dictation, and sent only with an AI rewrite. With **Hold to talk** (`holdToTalk`) a held shortcut records until it is let go and a lone tap cancels (a tap that latched the recording left an overlay listening that no one asked for) — read retroactively, as the Edit shortcut reads its own, because a double tap locks the dictation on hands-free until the next press; while the first shortcut is held, every tap of the other flips the mode, so a switch to AI can be taken back. A press of the held shortcut itself means its release was missed, and follows the press table.
- **AI recording** — Triggered by global hotkey (default: `Ctrl+Shift+A`). With no AI provider configured the shortcut is simply a second dictation shortcut (`AppState.effectiveKey`), rather than a dictation that ends in "AI processing skipped" every time. Same flow as inline recording, but before pasting, the transcription is sent to an LLM by `TextRefinementService`. The dictation itself is the prompt: the model picks the best-matching prompt preset from `whenToUse` descriptions, applies that preset's instructions, and returns only the resulting text. The model is also told which app, window and field the text is for (`FocusContext`, read when the recording starts), so an unstyled dictation comes out as a chat message in Slack and a letter in Mail. The overlay stays up (tinted purple, with a sparkles badge) while the LLM works. Any LLM failure or refusal falls back to pasting the raw transcript, so a dictation is never lost. With **Show the dictation while speaking, then swap in the AI version** (`aiDraftWhileSpeaking`, off by default) the raw text is pasted as it commits — Tier A only — and `InlineDelivery.deliverAIResult` replaces that draft with the rewrite in one write; if the replacement is refused, the rewrite is pasted anyway.
- **Edit selection with AI** — Triggered by global hotkey (default: `Ctrl+Shift+E`). Rewrites the text selected in the app in front: `PasteService.readSelection` reads it on the first press (through AX in Tier A, with the range; with a ⌘C and the clipboard put back otherwise), the microphone records an optional spoken instruction, and `TextRefinementService.edit` sends `<selected_text>` + `<instruction>` (+ `<context>`) under its own system prompt — with no instruction it polishes; with one, the presets are a vocabulary the instruction may name. The overlay is *filled* violet with the pencil-and-sparkle `EditGlyph` (AI dictation is only outlined), and the instruction is never pasted. See **An edit cuts the selection when the instruction ends, and puts it back on any failure** for the write.
- **Record Window** — Triggered by global hotkey (default: `Ctrl+Shift+W`). Opens `DirectRecordingPanel.swift`, a floating panel that auto-starts recording. The transport knob starts, pauses and resumes; the dot matrix along the bottom shows the level while recording and a sweeping comet while a provider is working. Transcribed segments land in an editable text column; while the column is still empty the transcript in progress is printed on the glass, with what has settled drawn brighter than the partial the recogniser may still take back. The button rail on the right inserts at the cursor or copies. The hotkey toggles recording when the panel is already open; ⎋ or ⌘W closes it, as does the ✕ that sits below the button rail, outside its recess. The rail's ✨ button turns on LLM processing: each time a segment finishes transcribing, the whole text area goes through `TextRefinementService` and is replaced with the result (turning it on with text already present processes it immediately), and the phosphor turns violet for as long as it is on.

### Services

- **`HotkeyManager.swift`** — Registers global hotkeys using Carbon `RegisterEventHotKey`. Supports four hotkeys (inline recording, AI recording, record window, edit selection), each with configurable key codes and modifiers, distinguished inside the one Carbon handler by `EventHotKeyID.id`. The handler takes both `kEventHotKeyPressed` and `kEventHotKeyReleased`: the two dictation shortcuts report each as `onDictationKey(key, isDown)`, the Edit shortcut as `onEditKey(isDown)`, the Record Window's only its press. `setEscapeShortcut(active:)` registers bare ⎋ as a fifth, temporary hotkey (`onEscape`): `AppState` asks for it only while the overlay is up and `escapeCancelsDictation` is on, because a Carbon hotkey is exclusive and ⎋ reaches no other app meanwhile; it is never registered while a shortcut recorder is listening. Listens for `hotkeyDidChange` notifications to hot-reload shortcuts, and unregisters everything between `hotkeyRecorderDidStart` / `hotkeyRecorderDidStop` — otherwise pressing one of our own combinations in a recorder would start a dictation instead of reaching it as a duplicate. A registration that fails is published per action in `HotkeyRegistrationStatus.shared.failures`, which Settings shows under the shortcut; `enabledSystemShortcuts()` reads the enabled macOS shortcuts via `CopySymbolicHotKeys`. Uses `Unmanaged` pointer for Carbon event handler callback.
- **`ShortcutConflicts.swift`** — `KeyShortcut` (key code + the four Carbon modifiers), `ShortcutAction` (the four shortcuts: title, defaults keys, built-in combination) and `ShortcutConflict.find` — a candidate that is another of our shortcuts or an enabled macOS one. Pure logic in both targets, covered by `ShortcutConflictTests`. What no API can list — another app's event tap or non-exclusive Carbon hotkey — is not checked.
- **`HotkeyRecorderView.swift`** — SwiftUI view (one per `ShortcutAction`) that captures a new keyboard shortcut via `NSEvent.addLocalMonitorForEvents`. Filters out bare modifier keys and requires at least one modifier; ⎋, closing a window or leaving the app gives up (every global shortcut is off meanwhile). Another of our own shortcuts is refused, not saved; an enabled macOS shortcut is saved with a warning, because the ones macOS really acts on never reach the recorder, so one that does is likely context-bound. A standing problem with the current shortcut — a collision, else a failed registration — is shown under the row. Also contains free functions `shortcutDisplayString()` (builds display string with modifier symbols) and `keyCodeToString()` (converts virtual key codes to readable strings using `UCKeyTranslate`). Defines the `hotkeyDidChange` notification name.
- **`PasteService.swift`** — Pastes text at cursor by saving clipboard contents, setting the clipboard to the transcription text, simulating `Cmd+V` via `CGEvent`, then restoring the original clipboard after a delay. Also handles app activation (via `NSRunningApplication.activate` + AppleScript fallback) and accessibility permission checks/prompts.

## Key Patterns

- **`@Observable` macro** — Used for `SpeechEngine`, `HotkeyManager`, `AppState`, `TranscriptionHistory` and `DebugLog` (Swift Observation framework, not Combine).
- **UserDefaults via `@AppStorage`** — All settings stored in standard UserDefaults. Keys defined in `SettingsKeys` enum.
- **`NSPanel` subclasses** — Floating panels use `.nonactivatingPanel` style so they don't steal focus from the user's active app.
- **Two skins, same capabilities** — `AppSkin` picks the chrome, never the feature set. `RecordingOverlayView` and `DirectRecordingPanelView` each keep both variants in one file, and the record window's buttons come from a single `railActions` list that both chassis render — so a button cannot exist in one skin and be quietly missing from the other. Closing the window is the one exception: techno draws its own ✕ below the rail, because minimal already has the system titlebar's close button and a second one beside it would be nonsense. Adding a third skin is a case in `AppSkin`, its two panel sizes, and a `body` branch in those two views.
- **Neutral is the default, a tint is opt-in** — `AccentColor.neutral` (an empty stored value) paints the level meter in `.primary` and the transport red, which is what the app has always looked like. An accent applied to *everything* turns a quiet sliver of glass into a coloured object, so the user has to ask for it. `Semantic.confirmation` keeps the copy/paste/send flash green regardless.
- **The accent belongs to the minimal skin only** — techno's every colour was matched against the design render, so `AppSkin.supportsAccent` keeps the user's colour out of it. AI mode's violet (`Semantic.ai`) is fixed in both skins: if it followed the accent, a user who picked violet would lose the one signal that tells a rewritten dictation from a plain one.
- **The window chrome is part of the skin** — minimal wears an ordinary titled `NSPanel`, so its rounded corners, the vibrancy behind `.ultraThinMaterial` and the close button all come from the system; reimplementing those only produces a worse copy. Techno is borderless because it draws its own moulded shell, and a titlebar there would sit on top of the moulding and swallow clicks meant for the knob. `DirectRecordingPanelWindow.applySkin()` swaps the `styleMask`.
- **Skin changes resize the window by hand** — the hosted SwiftUI reflows through `@AppStorage`, but the `NSPanel` around it does not, and the two skins are different sizes. Both panel classes observe `.skinDidChange` and call `setContentSize`.
- **One skin, two surfaces** — within the techno skin, the inline overlay and the record window are the same device. Every colour, radius and dot pitch lives in `TechnoSkin` (DesignKit.swift), so neither surface can drift from the other or from the Figma file.
- **Traced shapes keep their path data** — `LCDScreenShape` stores the two `d` strings Figma exported and scales them onto whatever rect it is given, instead of a hand translation into `Path` calls. Re-exporting a tweaked vector is then a copy-paste. The two halves are `union`ed, not merely overlaid: they share an internal edge at the knob's waistline, and the inner shadow strokes the shape, so anything less would draw a seam across the glass.
- **The knob is drawn, not exported** — `TransportKnob` rebuilds the design's layer stack (bevel → outer disc → groove → cap → glyph) in SwiftUI because the app needs the knob in states the design never drew (recording, transcribing, AI, hover, pressed) and a bitmap can't take a different glyph or tint. Its shading was matched against the design render pixel by pixel; changing a gradient stop by feel will drift.
- **The bevel is a `.background`, not a ZStack layer** — it is larger than the knob, and a `ZStack` re-proposes its final size to flexible children, so putting it in the stack silently inflates the disc to match it.
- **The display has its own clock, and bounces in place** — `PixelWaveform` runs at a fixed 30Hz and samples `barLevels` on each tick, rather than advancing when the audio tap fires: Core Audio's callback rate varies, so anything driven from it speeds up and slows down. Every column is redrawn from the *current* loudness (mean per-segment RMS, not the peak — one transient in any segment pins the peak to full height) times a hashed per-column jitter, so the grid jumps up and down like a hardware equaliser. The loudness goes through a compressive curve (`gain` then `pow(_, 0.7)`, above a noise floor) rather than a plain multiplier: raw RMS puts a normal speaking voice in the bottom row or two and reaches the top of the glass only when the user shouts. Columns ease towards their target (quicker up than down) instead of stepping onto it, the topmost dot fades in with the fraction of a row the column has grown into — eight rows are too coarse to move smoothly otherwise — and each lit dot carries a little hashed brightness variation, so the field reads as phosphor rather than as a chart. It deliberately does not scroll a history sideways: a track travelling across the glass reads as a progress bar rather than as a voice. The jitter is hashed from column and draw index instead of drawn from a random source, because a body re-evaluation has to reproduce the same grid; the rise is instant and the fall is eased, which is what keeps a syllable visible without the whole grid strobing.
- **Streaming rides alongside the audio file, never instead of it** — when the ElevenLabs model is `scribe_v2_realtime`, the fallback is *composition*: `StreamingRecognitionSession` wraps a `BatchRecognitionSession`, and the tap feeds the stream the 16 kHz Int16 bytes that `AudioBufferWriter.append` returns — one conversion serves both the file and the socket. The session keeps `committed` and `partial` apart (`RecognitionEvent.live(committed:partial:)`) and `SpeechEngine.liveText` is their join — so the Record Window's ghost text works exactly as it does for Apple. On pause/stop, `finish()` takes the stream's text; if the stream reported `failed`, or ended with nothing, the session clears the ghost text and hands over to the wrapped batch session, which uploads the same writer's file. History is written by the engine from the returned `RecognitionOutcome`, whichever half produced it. `RecordingConfiguration.batchModel` maps the realtime model ID to `scribe_v2` for that fallback (and for History retries), because the realtime model does not exist behind the upload endpoint. Whether ElevenLabs shows live text is therefore a function of the stored model (`streams`), not of the provider enum.
- **OpenAI's stream is a different shape, and the differences are absorbed in the provider** — `gpt-live-transcribe` (checked against the live service 2026-09-21) runs *no* voice-activity detection: `turn_detection` is rejected outright, so nothing is ever committed on a pause and one item stays open, growing, until `finish()` sends `input_audio_buffer.commit`. Its transcripts arrive as *increments* (`conversation.item.input_audio_transcription.delta`), not as the cumulative restatements `TranscriptMerge` is written against, so `OpenAIRealtimeProvider` accumulates them per `item_id` and emits `.partial` as the whole segment so far; the `.completed` event's `transcript` is authoritative and replaces them (it ran a word or two ahead of the deltas every time). The adapter stays in the provider — `TranscriptMerge` is not taught about deltas. Two more sharp edges: a fresh session has `transcription: null`, so `session.updated` (not the `session.created` before it) is the "server is ready" signal the pre-session buffer waits for, and the commit is refused below 100 ms of audio, which is why the tail is padded with `STTTuning.streamCommitPaddingSeconds` of silence exactly as Scribe's is. An empty-commit error resumes the wait rather than failing the stream; the stop then falls back to the upload, which has the whole segment on disk.
- **A stream that wants another rate converts from the tap, not from the file** — the socket's audio format is the provider's to declare (`StreamingSTTProvider.sampleRate`) and the caller's to satisfy; before OpenAI every provider happened to want the writer's 16 kHz, and `StreamingRecognitionSession` simply skipped a stream that did not. OpenAI's realtime session accepts *exactly* 24 kHz (16 kHz is "below minimum", 48 kHz "above maximum"), so the session now builds a second `PCMDownsampler` from the **native** tap buffer — 48 → 24 kHz in one step rather than 48 → 16 → 24 — and feeds the socket from that. ElevenLabs is untouched and still sends the writer's own bytes, so "one conversion serves both the file and the socket" still holds wherever it can. The converter is rebuilt when the tap's format changes, because a device restart hands it a new one mid-recording.
- **A streaming recording is built on the overlay, and pasted once** — Scribe's realtime VAD closes a sentence on a short pause ("…зробимо.") and re-states it a moment later once the user carries on ("…зробимо, потім"). The Record Window shows that correction because it owns its surface; text already pasted into another app cannot take it back, and Tier B cannot correct it at all. So when `RecordingConfiguration.streams`, `AppState` sets `showsLiveTranscript` and passes `livePreview` to `InlineDelivery.begin`: no span goes out while the user speaks, in any tier or mode (the `aiDraftWhileSpeaking` draft included), the overlay draws `spanLayer.stableText` + `segmentProvisionalText`, and the stop's ordinary paste — an empty ledger, so `FinalizePass` says `nothingDelivered` — is the one write. The tier probe is skipped for such a recording, since nothing would use its answer. The progressive path below is now reached only by Apple's on-device tier, whose commits arrive at its 50 s chunk rotation, and by the replays that pin it down — keep it working, but a change that only matters to streaming belongs on the overlay. `DictationTrace.Setup.livePreview` records which path a trace took, and `LiveTranscriptReplayTests` replay it.
- **Spans, not one re-joined string** — `RecognitionEvent.live(committed:partial:)` keeps the two halves apart, and `TranscriptSpanLayer` is what they are kept apart *for*: the increment of the cumulative `committed` string becomes a span, and the commit adopts the id of the partial that was showing those words, so a sink that already drew the partial can replace it in place instead of appending a second copy. The engine no longer stores `liveText` — it feeds the layer and computes `liveText` from `spanLayer.segmentText`, which keeps the per-segment meaning the views have always had (a pause hands its segment over for insertion and the ghost text starts again) while the recording's whole timeline survives in `spanLayer.text`. States carry the rules: `settled` and `frozen` are terminal, so a segment result, a provider that restates its committed text, and (later) the finalizing pass all refuse to touch what the user edited by hand. A segment result equal to what the spans already spell settles them where they stand rather than redrawing them — the smallest version of the spec's "replace only what differs".
- **Tiers, decided once, from what the sink proved it can do** — `DeliveryTier` (DeliveryTier.swift) answers one question: what may this recording hand over while the user is still speaking? Tier A is our own surface, or a foreign app whose text the Accessibility API can read *and* re-select; Tier B is everything else (Chromium and Electron answer inconsistently for `contenteditable`, terminals never answer at all). The probe's load-bearing step is the read-back — `PasteService.probeFocusedText` writes the selected range the element already has and compares what comes back, because Chromium returns `.success` on that write and then reports a different range, and a probe that trusted return codes would file VS Code under "correctable". The decision is pure logic so it is testable without an app to focus: `PasteService` does the AX I/O and hands the answers in as an `AXTextProbe`. It is taken once, at the start of the recording: a tier that changed halfway would mean text issued under one set of rules being corrected under another.
- **A span is issued once, and partials are issued to no one** — inline delivery pastes committed spans as they commit, which is what makes dictating into TextEdit show text while speaking. It never pastes a partial, in any tier: without a pass that can replace what a foreign app already holds, a partial pasted is a partial that can never be taken back, and that is the boundary invariant broken rather than served. Tier B's "committed only, and never rewritten" then holds by construction — `rewriteSegmentStable` reuses the first span's id, and `SpanIssuer` (TranscriptSpan.swift) never issues an id twice — rather than by anyone remembering to check. Emission stops at the first span that is still moving, because nothing can reorder text already pasted into another app. AI mode buffers by default in every tier: the LLM rewrites the whole dictation at the stop, so anything issued early has to be taken back — which only Tier A can do, so that is the only tier the opt-in draft is delivered in.
- **The ledger records the document's copy, and the stop subtracts it** — `InsertionLedger` (pure logic, both targets) is what each sink keeps: where a span landed and *what the sink actually holds there*. The sink's copy, not the string sent — a text view with substitutions on or an app that normalises line endings stores something slightly different, and a guard that compared against our version would refuse every correction it was asked to make. Two uses follow. `TextInsertionHandler.replaceSpan` and (later) phase C replace a span only where `resolve` can still find it: the recorded range if the text there matches, otherwise the one *unambiguous* occurrence elsewhere, otherwise nothing at all — two identical occurrences resolve to nothing, because "the last one" is a guess and a guess may not rewrite the user's document. And `remainder(of:)` is what stops the third doubled dictation: the stop pastes the authoritative text minus what the app already has, and when the final text *disagrees* with what is there rather than extending it (a streaming segment that fell back to a batch upload and came back worded differently) it pastes nothing at all. A slightly stale dictation beats two wordings of it stacked in the document. "Disagrees" is judged with a tolerance, though: a batch fallback re-words the delivered text starting with its least certain words — the first among them ("Зроблю…" → "Роблю…") — and `transcriptOverlap` needs that first word unchanged, so when it finds nothing `remainder` falls back to the words' longest common subsequence and accepts a re-wording that keeps `restatementAgreement` of them in order, pasting only what follows. Refusing there lost the sentence said after a Wi-Fi cut (17.09), and a genuinely different text still resolves to nil — for which `AppState` now shows "Part of the dictation wasn't pasted" (click → History) instead of saying nothing. A record with no range (a paste whose landing could not be read) is not a reason to refuse a correction on its own either: `resolve(_:in:)` finds it by its text, exactly once or not at all.
- **One write at the stop, before `.idle`** — `SpeechEngine.onFinalize` fires once the stop's text is in the span layer and before the phase goes idle, because `.idle` wakes `awaitTranscription()` and the stop's paste must see a ledger the pass already updated. It is handed `spanLayer.text`, the whole recording, not `finalText`: a device restart leaves `finalText` holding only its last segment, and "correcting" to that would delete what came before. `FinalizePass.decide` then says what happens: nothing delivered or a final text that only adds words — the stop's ordinary paste is the one write; a disagreement in Tier A with nothing frozen — replace; anything else — leave it standing. A replacement re-checks the tier first (the focused element taken at the start must still be focused in the app in front, and no span paste may still be landing), and `PasteService.replaceLastInsertions` checks again at every step — pid and value, plan, selection read back, `kAXSelectedText` write (⌘V over the confirmed selection if refused), caret to the end. The plan *refuses* on any unresolvable record where the spec says "skip": the write is one range across all records, so a skipped record inside it is the user's edit overwritten and one at an end is words pasted twice. No backspace is ever simulated. AI mode skips this pass: by default it delivers nothing early, so its paste is already the one write, and with the opt-in draft the one write is `deliverAIResult` replacing the draft with the rewrite once the LLM answers (the rewrite is given `spanLayer.text` for the same device-restart reason). A refused draft replacement pastes the rewrite anyway — the user chose getting the rewrite over keeping the draft out of the document. The Record Window is untouched too, which inserts only final segments and has nothing to correct.
- **Dictations are replayed, not hosted** — the test bundle cannot host the app, so it cannot run `SpeechEngine` or `AppState`; what it can run is everything between the provider and the document. `DictationReplay` (SpeechTextTests) feeds scripted `StreamingSTTEvent`s into a real `StreamingRecognitionSession` (its fallback is typed by the protocol, so the batch answer is scripted too), the events through `TranscriptSpanLayer` and `SpanIssuer`, and the spans into a real `InlineDelivery` whose target is `FakeApp` — a document in memory told how to answer the Accessibility API (TextEdit, terminal, Chromium, an Electron app that refuses the correction's selection). The engine and AppState glue between those pieces is repeated in `DictationReplay.run`, step by step with the source named; **a change to that order in `SpeechEngine.stopRecording` or `AppState.handleTranscriptionResult` has to be mirrored there**, or the replay tests a flow the app no longer has. Its first run found two bugs the checklist had not: a span committed while the target app was not in front was dropped, and a terminal lost that sentence silently; and a span still landing when the stop was handled was pasted twice. What a replay cannot show is whether a real app answers AX the way `FakeApp` was told to — that stays in docs/manual-testing.md. Real dictations become fixtures through `DictationTrace`: Debug Log › Record traces, `scripts/import-trace.sh`, and `RecordedTraceTests` replays them (the recorded pastes must recur, or a reviewed `expectedDocument` must).
- **A segment boundary is a space unless the provider cut a word** — Scribe's realtime VAD closes a segment on a moment's silence, and a stumble inside a word splits it ("…база дани" | "х, звідки", 17.09). `segmentSeparator` (TranscriptMerge.swift) glues a boundary only when the first segment ends in a letter, the next opens with a lowercase letter, the halves together are a word and the second half alone is not. Words are checked by `TranscriptJoin.isWord`, which `registerSpellCheckedJoins()` (App.swift) points at `NSSpellChecker` at launch — the language follows the script, because the English checker accepts any Cyrillic word — and one-letter fragments are judged by `TranscriptJoin.oneLetterWords` instead, because a spell checker accepts every single letter. Unregistered it glues nothing. The decision is made once, in the streaming merge (`joinedSegments`), and carried from there: `TranscriptSpan.joinsPrevious` is read off the cumulative committed text, the live paste and `InsertionRecord` honour it, and `InsertionLedger.pasteableRemainder` cuts the stop's tail off the final text character for character when it can, so the tail's separator is the provider's own. Run over all 300 History records (5,077 word boundaries treated as cuts) the rule glued one pair, an English "de | ne"; "Чи | я" was the other until "я" joined the one-letter list.
- **Clipboard restores coalesce across a burst, and yield to the user** — several pastes per recording broke the save/restore pair that protects the user's clipboard: the second paste's save read back the *first paste's text*, so a second later the user's clipboard held a fragment of their own dictation. `PasteService` takes the snapshot once per burst and cancels and reschedules the pending restore instead of stacking a second one behind it. The restore also compares the pasteboard's `changeCount` with the one recorded when our text went on: a ⌘C the user pressed mid-dictation changes it, and putting the old snapshot back over that copy would be the same bug from the other side.
- **⌘V, ⌘C and ⌘X are looked up in the layout, never hard-coded** — a virtual key code names a position, and 0x09 is V only on QWERTY: on Dvorak the paste did nothing and the Edit shortcut's ⌘X cut nothing, or something else. `PasteService.commandKeyCode(for:)` asks the current layout (`TISCopyCurrentKeyboardLayoutInputSource` + `UCKeyTranslate`) which key types the letter *with ⌘ held* — that is what makes Ukrainian and "Dvorak – QWERTY ⌘" answer with the QWERTY position — trying the ANSI position first and falling back to it. Not cached: it runs per paste and costs nothing. Everything we stage on the pasteboard also carries `org.nspasteboard.TransientType` / `AutoGeneratedType`, so clipboard managers do not archive each dictation (never `ConcealedType`, which some apps refuse to paste), and the process-wide AX messaging timeout is 1.5 s instead of the system's 6 s per call, so a hung app cannot hold a stop for half a minute. `IsSecureEventInputEnabled()` is only *logged* with each paste: it is not established that secure input blocks a posted ⌘V, so nothing is refused on it.
- **A silent segment is not uploaded** — Whisper answers silence with "Thank you for watching", which would be pasted. `AudioBufferWriter` tracks the peak of the converted samples and `BatchRecognitionSession.finish` returns an empty outcome — after writing the file, so it is still archived for a History retry — when it never reached `STTTuning.silencePeakFloor` (−44 dBFS: a muted or dead microphone, a shortcut pressed with nothing said; room noise above it still goes to the model). Native-fallback audio is unmeasured and counts as audible. History retry calls the provider directly and is not guarded.
- **Sessions, not provider branches; one per segment, the archive stays with the engine** — `makeRecognitionSession` is the only place that knows which tier a configuration selects, so `SpeechEngine` has no *per-segment* `if provider == …` recognition branches — the one remaining `provider == .apple` test in `setupRecordingSession` caches the `SFSpeechRecognizer` across sessions to keep the speech model loaded, which is exactly why it cannot live inside a per-segment session; it builds a fresh `RecognitionSession` for every segment (a resume is a new session), but the `AudioBufferWriter` and the History calls stay in `SpeechEngine`: the writer must exist for every tier (it is the batch upload, the stream's fallback *and* the archive kept when on-device recognition returns nothing), and the tap must be gone before it is dropped — `cleanup` tears the engine down before resetting the writer for exactly that reason. Sessions report; the engine records.
- **One phase enum, booleans are views over it** — the engine's state is the single stored `RecordingPhase`; `isRecording`/`isPaused`/`isTranscribing`/`isStartingEngine` are read-only computed properties. When these were four stored flags, a stop that set `isRecording = false` a line before it set `isTranscribing = true` could be observed in between as "idle" — a phase write is atomic. `@Observable` tracks the computed getters through the stored `phase`, so every view keeps updating without change. `awaitTranscription()`'s waiters resume from `phase`'s `didSet` on the `isTranscribing` true→false *edge*; `paused(segmentInFlight: true) → finishing` is deliberately not an edge, because a stop that arrives while a paused segment is still uploading is now waiting on that same segment. `segmentFinishStarted` stays a separate flag on purpose: "this segment's audio was already sent" is not a phase — it survives `paused(true) → paused(false)` and is what stops a stop-from-paused from uploading the same audio twice. `cleanup()` never writes `phase`; every caller sets `.idle` immediately before calling it, after its result fields are in place, so a resumed waiter always sees a finished result. The Debug Log shows one `phase: a → b` line per transition instead of three flag lines.
- **The socket opens before the microphone does** — `setupRecordingSession` calls `session.start()` (and so the realtime provider's `connect`) before `installAudioTap` and before the background `prepare()`/`start()`, so the TLS handshake overlaps the 100–300 ms the hardware takes. Audio the tap produces before the server's `session_started` is held in `ElevenLabsRealtimeProvider.preSessionMessages` — already encoded as socket messages, so the flush is only `task.send` calls and never stalls the audio thread (it runs under a separate `sendLock` that orders the socket's batches; holding the state `lock` across a send would deadlock against a synchronously-delivered send completion, whose `fail` → `close` path takes that same lock) — and released when it arrives, so the first syllable is neither dropped nor reordered behind later chunks; a `finish()` before the session started sends what was held ahead of the commit. `send` takes `sendLock` *before* it empties `pendingAudio` and holds it until the chunk is on the socket: released between the two, a `finish()` could win the lock in the gap, find nothing pending, commit only its padding, and the chunk would land after the commit in a segment that never closes — up to 100 ms of the last word. If the bound (`STTTuning.streamPreSessionBufferSeconds`) fills, the stream *fails* rather than dropping the oldest audio: a transcript missing its opening seconds must not be recorded as a success, and the batch fallback has the whole segment on disk. `finish()` likewise does not trust the first `committed_transcript` it sees — the server answers in order, so a VAD segment closed just before the stop lands first — and waits `STTTuning.streamCommitGraceSeconds` for a partial that would show the final segment is still coming. The partial that shows it, though, must be a *new* one: Scribe also re-sends a segment it has just committed as one more `partial_transcript`, and taken at face value that echo both joins the same words on twice (the dictation pasted doubled) and holds `finish()` for its whole timeout waiting on a segment that will never be committed — so `ElevenLabsRealtimeProvider.isEchoOfCommitted` drops a partial equal to the last committed text. That equality is only the first frame of the echo, though: keep talking and the re-statement *grows*, arriving as the whole accumulated transcript with a word or two revised, which an equality test cannot see. So `StreamingRecognitionSession` does not join what the stream reports — it merges it (`TranscriptMerge.swift`): `mergedTranscript` replaces the committed text with a re-statement of all of it (the server's later version saw more audio) and `transcriptContinuation` reduces a partial to what it adds. Word-level comparison, punctuation-insensitive, with a `restatementAgreement` tolerance for the revised words and a `minimumRepeatedWords` floor below which a repeat is taken for speech rather than for a re-send.
- **Hesitations are cleaned before they become spans** — `no_verbatim=true` is echoed back by the server and Scribe still writes Ukrainian "е-е-е", so `SpeechEngine` runs `configuration.cleaned` on every `.live` event, on Apple's `pause()` text and on each `RecognitionOutcome`, and History retry does the same. Not at the stop: spans are pasted while the user speaks, and a stop whose text no longer extends them is read by `InsertionLedger.remainder` as disagreement and pastes nothing. That is also why `cleanedTranscript` must be monotone on whole-word extensions — a rule may rewrite a word only from that word and what came before, never edit a word already written (a filler's full stop is dropped rather than moved onto the previous word). History therefore stores the cleaned text as `record.text`: cleanup counts as transcription quality, and "raw" in the Refinement sense means "before the LLM".
- **Scribe quality flags are sent explicitly** — the upload API's `tag_audio_events` defaults to *true*, which would paste "(laughs)" into a document, so `ElevenLabsSTTProvider` sends it off; `no_verbatim=true` goes on both the upload and the realtime query string (fillers and false starts dropped server-side; documented for scribe_v2). The batch model IDs in `elevenLabsModels` are exactly what the API's `unsupported_model` error lists (`scribe_v2`, now that `scribe_v1` is deprecated and `scribe_v1_experimental` gone); the realtime ID exists only behind the WebSocket.
- **`.task` captures the view by value** — which is why `PixelWaveform` reads levels through a small `LevelFeed` class rather than its own stored property, and why the task is keyed on `mode`.
- **Two signatures, and the one that survives a team change is ours** — an update is trusted twice over: Apple's Developer ID makes the app openable, and an EdDSA key that belongs to this project makes the *download* ours. They are deliberately independent. The Apple team ID is part of the identity macOS keys every permission grant to, and moving the account to another team (converting it to an organization, say) changes it — with a key of our own, the update still installs and only the permission prompts come back. `scripts/make-appcast.sh` signs each release and writes the feed; `scripts/package-release.sh` refuses to build a distributable image whose `Info.plist` has no `SUPublicEDKey`, because an app that cannot be updated looks fine right up until the next release cannot reach anyone. The feed carries one item, the release being cut: Sparkle installs the best item it finds, so a release needs nothing from the one before it.
- **Three dependencies, one file each** — WhisperKit, FluidAudio and Sparkle are the project's only third-party code, a decision recorded in ROADMAP.md: Whisper needs a tokenizer and a decode loop that Core ML does not supply (and whisper.cpp publishes no macOS binaries to run as a sidecar), Parakeet needs a TDT decode loop and a mel frontend it does not supply either, and an app distributed outside the App Store needs a downloader, a signature check and an installer able to replace a running app. Everything around each of them is Foundation — for the two speech engines the catalogue, the hardware read, the recommendation, download bookkeeping, the provider shape and the Settings UI; for Sparkle the menu item, the settings rows and the packaging. `import WhisperKit` appears only in `LocalWhisperRuntime.swift`, `import FluidAudio` only in `LocalParakeetRuntime.swift`, and `import Sparkle` only in `UpdateChecker.swift`. That is what keeps the standalone test bundle building, and it makes replacing any of them one file. FluidAudio also pulls a prebuilt Rust `NemoTextProcessing.xcframework` for text normalisation we never call; it is a static `.a`, so it links into the binary and adds nothing to sign or embed.
- **Registration, not imports, for the local tier** — `STTProvider.swift` is in the test subset, so its `makeBatchProvider` switch cannot name `WhisperKitLocalProvider` or `ParakeetLocalProvider`. It calls `LocalSTT.providerFactory`, which `registerLocalSTT()` (LocalModelStore.swift) points at the real engines at launch, dispatching on the catalogue entry's `LocalSTTEngine`. The unregistered default throws `LocalModelError.notInstalled` rather than returning "" — an empty success would skip the failure paths that keep the audio for a History retry. Two engines behind one `STTProviderType.local` is deliberate: "a model on my Mac" is one choice to the user, and a second provider case would have doubled the recognition tier, the History archive, retry and onboarding to describe a difference they never make.
- **The local tier is a batch tier** — `.local` goes through `BatchRecognitionSession` like Groq, so the engine, the History archive and retry need no new branches, and that holds for both engines. Retry asks `RecordingConfiguration.batchUnavailableReason()` instead of testing a key: the local tier needs an installed model, and "add a Groq key" would be the wrong advice. FluidAudio does ship a sliding-window streaming manager, so a live local preview is possible later; it is deliberately not wired up, because `makeStreamingProvider` is keyed off the cloud engines and the confirmed/volatile split would have to be mapped onto the span layer.
- **Load once, decode one at a time** — the expensive part of local Whisper is loading, not decoding: a Core ML model's first load on a Mac specialises it for the Neural Engine — 45 s for Small and **9 minutes** for Turbo on an M1 Pro. `LocalModelStore` shows that as its own `InstallState.optimizing` ("installed" while nothing seemed to happen was the alternative); the model is `isUsable` meanwhile, and a dictation simply waits for the same load. `WhisperKitPipelineCache` keeps one pipeline resident, `LocalModelStore` prewarms right after install so that cost lands in Settings rather than in front of the first paste, and jobs are chained because an actor re-enters at every `await` and a pause followed quickly by a stop can finish two segments at once. `WhisperKit` is not `Sendable`, so the pipeline never leaves the actor.
- **The tokenizer lives in the model folder** — it is not part of the Core ML download; WhisperKit fetches it on first load and by default writes it to `~/Documents/huggingface`, which raises the macOS Documents-folder prompt and leaves it outside anything Remove deletes. `tokenizerFolder` is set to the model folder (one of WhisperKit's own search paths), so the post-install prewarm fetches it once, while online, next to the model.
- **Model storage and the rename migration** — models live in `Application Support/SpeechText/Models/`, inside the folder `adoptPreRenameStore()` moves wholesale. That migration only runs when `SpeechText/` does not exist yet, so `LocalModelStore.install` touches `TranscriptionHistory.shared` before creating anything, and `SystemCapabilities` measures free space on the Application Support *root* rather than creating `SpeechText/` to ask.
- **Tiers pick two models, and candidates step down** — `MacTier` (by memory) selects a `TierPicks`: *recommended* is the fastest model of good enough quality, because the user is waiting on the paste; *best quality* is the strongest the tier can hold. Each is a candidate list, and `firstFitting` takes the first that clears its RAM floor and fits on disk, so a Mac at the bottom of its tier (24 GB in the 24–32 GB tier, 96 GB in the 96–128 GB tier) or with a nearly full disk steps down instead of overfilling. Speech excludes the large models on Intel (no Neural Engine — a hardware fact, not a memory shortage, and it rules out Parakeet for the same reason); chat does not, because Ollama runs on Metal. Speech does not scale with the Mac at all — every Apple Silicon tier gets Parakeet v3 for both picks, so a Mac Studio with 512 GB transcribes with the same model a 16 GB MacBook Air does, only faster — and chat stops at 128 GB, because everything bigger in Ollama (Qwen3.5 397B, MiniMax M2.7, Kimi K3, Mistral Large 3) is `:cloud`-only. **The 8–32 GB picks are measured** (2026-09-17, M1 Pro 32 GB, Ollama 0.34.1, six dictations through the app's own prompt and parser): Qwen3.5 2B failed (Ukrainian turned Russian), 4B was usable with misroutes, Qwen3.5 9B and Gemma 4 12B handled all six at 2–4 s with Gemma cleaner — so Gemma 4 12B leads 16–32 GB — and Qwen3.8 27B wrote the best text at 5–14 s, hence *best quality* only. On speech, Whisper Small and Base answered Ukrainian in Russian spelling (38–100% WER) while English was perfect, and the full Large v3 reproduced Turbo's errors word for word ~30% slower — so no tier is steered to it. **Parakeet v3 was measured on 2026-09-21** against a real 12.4 s Ukrainian dictation — not `say -v Lesya`, which every engine transcribes near-perfectly and which therefore discriminates nothing: it returned the same text as ElevenLabs Scribe v2, where cloud Whisper Large v3 Turbo (the same weights as the local Turbo variant, unquantised) misread the first word, and it answered in 0.34–0.61 s from a cold process against Turbo's nine-minute first-load specialisation on this Mac. At 483 MB to Turbo's 645 MB there is no tier where Turbo fits and it does not, so it leads all of them. The caveat is honest: that is one sentence of real speech, and a longer dictation is the confirmation. The 36 GB+ picks are **not** measured (no such hardware); Gemma 4 26B leads the pro tier as the MoE sibling of the 16–32 GB winner.
- **Ollama is the user's, not ours** — the app cannot install Ollama itself without downloading an executable, so the not-running state links to ollama.com; after that, models are one click. Any model already in Ollama is offered alongside the catalogue, and `ollamaModel` is therefore not normalised against it. `reasoning_effort` is sent because every candidate thinks by default (2.0 s vs 0.22 s for the same clean-up on Qwen3, measured on Ollama 0.18.1) — `none`, except `low` for gpt-oss, which rejects `none`; `think: false` is silently ignored on this endpoint.
- **Small models write the mode marker loosely** — Qwen3.5 2B/4B/9B emitted `<<Email>>`, `<mode:Translate>…</mode:Translate>` and `<<mode:Clean-up>` instead of `<<mode:NAME>>`, and the strict parser left those in the pasted text. `TextRefinementService.parse(_:allowing:presetNames:)` also takes a loose first-line marker (and a trailing closing tag), but only when the name is exactly one of the presets, ignoring case — a reply that genuinely begins with `<div>` stays untouched.
- **Every local chat model carries the Ollama version it needs** — an older daemon does not refuse the pull: it downloads gigabytes and then fails every request with "unable to load model" (Ollama 0.18.1 with Qwen3.5; "unknown model architecture" appears only in its server log). `minimumOllamaVersion` comes from Ollama's release notes (Qwen3.5 0.17.4, Gemma 4 26B/31B 0.20.0, Qwen3.6 0.24.0, Gemma 4 12B 0.30.5 — 0.30.3 added it but crashed, Qwen3.8 0.32.12, gpt-oss 0.11.0). Settings compares it with `/api/version` and swaps Download for "Update Ollama…"; `OllamaLLMProvider` turns that 500 into `OllamaError.needsUpdate` only when the version check confirms it, because the same words also mean out-of-memory.
- **Cloud catalogues are checked against the vendor, not remembered** — last on 2026-09-16. Groq shut Llama 3.3 70B (the old default), Llama 3.1 8B, Qwen3 32B and Kimi K2 down for free and developer accounts, so `groqChatModels` is gpt-oss 120B/20B plus two labelled previews, and normalisation moves stored IDs to `openai/gpt-oss-120b`. Groq's reasoning switches differ per family and the wrong one is an HTTP 400: gpt-oss takes `reasoning_effort: low` + `include_reasoning: false` and rejects `reasoning_format`; Qwen takes `reasoning_effort: none` + `reasoning_format: hidden` (its default `raw` puts `<think>` into the content); `OpenAICompatibleLLMProvider` also runs `strippingReasoning` for a model that documents no switch. ElevenLabs deprecated `scribe_v1` and dropped `scribe_v1_experimental`, so `defaultElevenLabsModel` is `scribe_v2` — the default, the realtime stream's fallback and History retries alike. The Anthropic and OpenAI defaults are the fast end (Sonnet 5, GPT-5.6 Luna); Fable 5.1 and GPT-6 Astra are left out as slow and expensive for a clean-up. Current Ollama returns any reasoning in a separate field — `strippingReasoning` is the fallback for older builds that put it inline, where it would push `<<mode:NAME>>` off the first line.
- **Carbon Events API** — Global hotkeys use `RegisterEventHotKey` / `InstallEventHandler` from Carbon.HIToolbox (the only way to register system-wide hotkeys on macOS).
- **No app sandbox** — Disabled in entitlements to allow accessibility APIs (`AXIsProcessTrusted`) and global event taps.
- **Clipboard preservation** — `PasteService` saves and restores clipboard contents around paste operations so the user's clipboard is not clobbered.
- **A device change keeps the segment** — `.AVAudioEngineConfigurationChange` under a live recording rebuilds only the `AVAudioEngine` and its tap (`restartAudioEngine`): the `AudioBufferWriter` is re-prepared for the new hardware format and keeps appending to the same 16 kHz buffer, and the cloud/local `RecognitionSession` never sees a boundary. Rebuilding the whole session, as this used to, replaced the writer before its audio was written and cancelled a batch session whose `cancel()` is a no-op — the first half of a Groq or local dictation vanished, with no History row, when AirPods connected mid-sentence. Apple's request takes native buffers, whose format just changed, so that tier (and a writer already on its native fallback path) goes through an ordinary pause and resume instead. More than five changes in ten seconds (`deviceRestartBudget`) — a headset that will not settle, where each restart raises the next notification — end the recording with what was said instead of looping. A change while *paused* only discards the stale engine: the resume builds a fresh one anyway, and going idle left the Record Window showing a pause the engine had abandoned. Engine `prepare()`/`start()` and every `stop()` run on one serial `engineQueue`, because a cancel that stopped the engine on main while a start was mid-flight on a background queue mutated one `AVAudioEngine` from two threads. The stop is queued asynchronously (waiting would stall main for a slow Bluetooth start) except before a restart's re-`prepare` of the writer; a start's success block moves the phase only from `.starting`, so a pause or stop that landed during a restart is not overwritten by `.recording`. The stop then pastes `spanLayer.text`, the whole recording, rather than `finalText`'s last segment, and an Apple pause writes its segment's History row as the batch tier does.
- **A start that fails says so** — `SpeechEngine.onStartFailure` fires (before `.idle`) when the session cannot open or the engine will not start; `AppState` takes the overlay down and shows a status notice. Nothing else reads `errorMessage` until a stop, and a failed start never reaches one, so the "preparing" overlay used to sit on screen until the next hotkey press. `startRecording` also ignores any phase but `.idle`: a start during `.starting` rebuilt the session under itself, and one during `.finishing` cancelled the stop's result.
- **Settings are snapshotted per session** — `SpeechEngine.startRecording` reads a `RecordingConfiguration.current(locale:)` once and every later step (pause, resume, stop, the stream fallback, the device-change restart) uses that copy; only `locale` is updated, by `resumeRecording(locale:)`. Before this, each step re-read UserDefaults, so changing the engine picker while the mic was live could send the second half of a recording to a different provider than the first. Two consequences are deliberate: provider, model and API key are frozen at start, and the batch upload's `language` is the segment's `cloudLanguage` captured at start/resume rather than `resolvedLocale()` re-read at stop (the Apple path already worked that way). History retry is the exception — it reads a fresh configuration, because a retry exists to try the settings the user has *now*.
- **Stored-value normalization** — `normalizeStoredProviders()` (Settings.swift) runs at launch and from the Settings view: a `sttProvider`/`llmProvider` string that no longer maps to a case is reset, and every stored model ID is checked against its catalogue (vendors retire whole generations, e.g. OpenAI's GPT-4.x → GPT-5.6). Without it the picker finds no matching tag and renders *blank* while the engine silently falls back to its default — the UI shows nothing and the app runs something the user didn't pick.
- **A default nobody stored is still a setting** — `normalizeStoredModel` ignores an *absent* key on purpose, and nothing writes `localSTTModel` until the user opens the model picker: `@AppStorage` and `RecordingConfiguration.current()` both read through to `defaultLocalSTTModel`. So moving that default is not the harmless edit it looks like — when it went from Whisper Turbo to Parakeet, every install running the local tier on the old default would have been pointed at a model it had never downloaded, and the next dictation would have failed with "Parakeet v3 isn't installed". `preserveInstalledLocalModel()` (Settings.swift) closes it: an absent key plus a model on disk is written down as the user's choice — the old default first, else the heaviest installed. A fresh install has nothing on disk and falls through to the new default, which is the point of moving it. Any future change to `defaultLocalSTTModel` has to go past that function.
- **Rename migrations are opt-in per key** — `SettingsKeys.portable` lists what crosses the bundle-identifier change, rather than copying the whole old domain. A blanket copy would bring `hasRegisteredLaunchAtLogin` (and the `didAdoptPreRenameDefaults` marker itself) with it, leaving the new app convinced it is already a login item when the registration belongs to a bundle identifier that no longer launches.
- **One-time shortcut migration** — `AppDelegate.migrateHotkeyLayoutIfNeeded()` clears stored hotkey values once (guarded by `hotkeyLayoutVersion`) so a changed built-in layout reaches existing installs; later customisations survive because the version has already been bumped.
- **Auto language detection is Apple's problem, not the cloud's** — On "Auto (System)" `resolvedLocale()` reads the active keyboard input source and maps it to a locale, because `SFSpeechRecognizer` must be handed one. A cloud provider is handed *nothing*: `RecordingConfiguration.cloudLanguage` is nil on Auto, and Whisper and Scribe detect the language from the audio. Forcing the layout's guess on them was a data-loss bug, not a mis-spelling — dictating Ukrainian with a US layout sent `language_code=en`, and Scribe answered with a two-second English *translation* of an eleven-second recording (History's own records: every truncated or transliterated entry carried `locale=en`, and 70 of 91 `en` records held Cyrillic text). History records `historyLocale` — "auto" when the model chose — so a record never claims a language that was never requested, and a retry takes the language from the current settings rather than repeating the guess.
- **The focus context is data, and the system prompt always describes it** — window titles and field labels are written by other people (an email subject, a web page's title), so the context goes in the *user* message as a `<context>` block with angle brackets defused, and the system prompt says it is a hint for the form of the output that the transcript always overrides and that nothing inside it is an instruction. That system-prompt section is always included, even for a dictation that has no context (the Record Window, a password manager): the system prompt stays identical from one recording to the next. The context is read in `startRecording` *after* the engine has been asked to start, unlike the tier probe: only the LLM pass after the stop consumes it, and its AX round trips to a slow app would otherwise delay the tap. The Debug Log records the app but not the window title, since every entry also goes to the system log as public. History keeps it on `Refinement.context`, so a preset choice that looks wrong can be traced to where the model thought the text was going.
- **An edit cuts the selection when the instruction ends, and puts it back on any failure** — while the user speaks the instruction the selection stays where it is (reading it changes nothing). The moment the instruction is over (the second press, the release, a double press) it is cut with ⌘X, so nothing the user does while the LLM works can make the rewrite land on the wrong text: the caret is where the selection was, and the rewrite is a plain paste there. Softer ways for the text to go were tried on 19.09 and removed at the user's call as not worth their complexity: a violet shimmer laid over the selection in a window of our own (did not look right), and erasing it word by word with AX-selected ⌫ steps (worked in TextEdit; Chromium applies AX selections late and reports an emptied field as its placeholder, and every workaround added another failure path). The cut is checked before it counts: in Tier A `PasteService.select` first finds the recorded words untouched (`InsertionLedger.resolve`) and re-selects them, and in every tier what the ⌘X took must be the text that was read — anything else is pasted straight back and the edit stops. The ⌘X keeps every pasteboard type the app wrote, so a cancel, an instruction that could not be transcribed, an LLM failure or a rewrite that changes nothing pastes the *original* back, formatting included (`putBack`). Never through `kAXSelectedTextAttribute`: T3 Code (Electron) accepts that write with success and ignores it. A field where ⌘X changes nothing (read-only) keeps its text and the rewrite goes to the clipboard. The rewrite itself is plain text, so formatting inside a selection that *was* rewritten does not survive. A dictation shortcut pressed during an edit cancels it (its recording is an instruction, and a mode switch would paste it), and the Edit shortcut is ignored while a dictation runs. History stores the edit as a `Refinement` with `editsSelection`: `inputText` is the selection, the record's `text` the instruction (empty with none). An instruction that came back empty is not written to History on its own (`SpeechEngine.recordsEmptyOutcomes` is off for an edit): it is the same as a double press.
- **Preset routing in one call** — The LLM both picks the preset and applies it in a single request; it reports its choice on a leading `<<mode:NAME>>` line that `TextRefinementService.parse` strips. This avoids a separate router round-trip, which matters because the user is waiting for the paste.
- **Graceful LLM degradation** — Every LLM failure path (missing key, HTTP error, refusal, empty response) falls back to the raw transcription rather than producing nothing, surfaces a status overlay, and is written to the history entry so a silently-unrewritten paste is explainable after the fact.
- **Attaching the LLM pass to a history entry** — `SpeechEngine` writes the history record, but refinement happens later in `AppState`/`DirectRecordingPanelView`. The engine exposes `lastRecordID` (cleared on each new session) so the LLM step can update that entry instead of creating a second one. A successful retry clears any refinement, since it described text that no longer exists.


## First run

A new install opens the setup window instead of asking for the microphone and Accessibility in two unexplained alerts at launch (`AppDelegate.decideSetupGate`). An install that predates setup — a login item already registered, or any `portable` setting stored — is marked done and never shown it. Setup writes each step's choice on its Continue: the speech engine explicitly (the Apple default knows no Ukrainian; ElevenLabs gets `scribe_v2_realtime`, since the card promises live words), the AI provider only if one was chosen ("Skip for now" writes nothing). Closed half-way, it opens again at the next launch on the step it was left on; the status menu's "Continue Setup… / Set Up SpeechText…" opens it any time. Its Try it step runs the real shortcuts and the real overlay, but `AppState` hands the result to `DictationTest` instead of pasting — the app never pastes into its own windows — and ignores the shortcuts while the chosen local model is still downloading or being prepared.

## Permissions Required

- **Microphone** — For audio capture (`AVAudioEngine`). `requestMicrophoneAccess` runs from `applicationDidFinishLaunching`.
- **Speech Recognition** — For Apple on-device STT (`SFSpeechRecognizer`). There is no explicit `requestAuthorization` call: the system raises the prompt the first time an Apple segment starts a recognition task, so a user who only ever runs a cloud engine is never asked for a permission the app would not use. `NSSpeechRecognitionUsageDescription` is in Info.plist for that prompt.
- **Accessibility** — For simulating `Cmd+V` paste via CGEvent. Must be granted in System Settings > Privacy & Security > Accessibility. `AppDelegate` prompts at every launch where it is not already granted (not once ever): the grant is revocable and is attached to the app's code signature, so a rebuild or an OS update can silently drop it, and a paste that quietly does nothing is the failure this avoids.
- **Automation** (`NSAppleEventsUsageDescription`) — Only for `PasteService.activateApp`'s fallback, when `NSRunningApplication.activate` fails to bring the target app back: an AppleScript `activate` sent to that app. macOS asks per target app the first time it runs.
